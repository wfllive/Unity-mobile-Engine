# Инструкция по запуску

Всё, что нужно — **Node.js 18+**. JDK, Android SDK и Gradle не требуются даже для сборки APK.

---

## 1. Установка

```bash
git clone https://github.com/wfllive/Unity-mobile-Engine.git
cd Unity-mobile-Engine
git checkout arena/01a01ed8-unity-mobile-engine
npm install
```

## 2. Запуск в браузере

```bash
npm run dev
```

Откройте **http://localhost:3000** — откроется **список проектов**. Это главная страница
приложения: здесь проекты создаются, переименовываются, копируются и удаляются.

Первым делом `npm run dev` собирает рантайм для APK, потом поднимает Vite. Это нормально,
что в логе сначала появляется строка «WFL: рантайм собран».

Сервер слушает `0.0.0.0`, так что с телефона в той же сети можно зайти по адресу
`http://<ip-компьютера>:3000`.

## 3. Как устроено приложение

Три экрана, между которыми вы переключаетесь:

| Экран | Что это | Как попасть |
|---|---|---|
| **Главная** | список проектов | стартовый экран, кнопка «назад» в редакторе |
| **Редактор** | сборка сцены | кнопка «Редактор» на карточке проекта |
| **Игра** | запущенная игра во весь экран | кнопка «Запустить» на карточке или «Играть» в редакторе |

Проекты хранятся в браузере (`localStorage`) и переживают перезагрузку страницы.
Каждый проект — это сцена плюс настройки сборки APK (имя приложения, пакет, версия).

**Создать проект:** кнопка «Создать проект» внизу справа. Выберите шаблон:

- **Пустая сцена** — земля, свет и камера;
- **Платформер** — игрок от третьего лица и платформы;
- **Физика** — башня из ящиков и шар;
- **Демо-арена** — готовая игра со сбором кристаллов, врагами и победой.

Проект можно выгрузить в файл (`Экспорт в файл`) и позже вернуть кнопкой импорта
в шапке главной страницы.

## 4. Редактор сцены

Интерфейс рассчитан на пальцы: всё делается тапом, клавиатура нигде не обязательна.

- **Сверху:** кнопка возврата на главную, имя проекта и зелёная кнопка **«Играть»**.
- **Слева:** перемещение, поворот, масштаб, привязка к сетке, «показать объект».
- **Справа:** добавить объект, дублировать, удалить, «ещё» (сохранение, APK, блюпринт, экспорт).
- **Снизу:** выдвижная панель с тремя вкладками — «Объекты», «Свойства», «Консоль».
  Потяните за строку вкладок или нажмите стрелку, чтобы свернуть/развернуть.

**Управление камерой:** один палец — вращение вокруг точки обзора, два пальца — зум и
перемещение. Короткий тап по объекту выбирает его; выбранный объект можно двигать
стрелками-гизмо. На десктопе работают мышь и колесо прокрутки.

Изменения сохраняются автоматически (каждые 20 секунд, при выходе и при запуске игры).

## 5. Запуск игры

Кнопка **«Играть»** в редакторе или **«Запустить»** на карточке проекта. Игра занимает
весь экран, редактор скрывается, включаются джойстик и экранные кнопки.

- **Пауза** — кнопка в правом верхнем углу (или `Esc` на десктопе). В паузе доступны
  «Продолжить», «Начать заново» и «Выйти из игры».
- **«Начать заново»** перезапускает сцену из исходного состояния — страница при этом
  не перезагружается.
- **«Выйти из игры»** возвращает ровно в тот редактор, из которого вы стартовали;
  все правки сцены сохраняются.

Если в сцене есть подбираемые предметы, сверху слева появится счётчик, а при сборе всех —
экран победы. Если у игрока есть компонент «Здоровье», рядом появится полоска здоровья.

## 6. Редактор блюпринтов

Выделите объект, откройте меню **«Ещё»** справа и выберите **«Блюпринт объекта»**
(или нажмите «Открыть граф» в инспекторе компонента «Блюпринт»). Если компонента
на объекте нет, он добавится сам.

Быстрый старт: нажмите **«Шаблон»** — вставится готовый пример (сообщение при старте
и вращение 90°/с), затем **«Применить»**.

- **«+ Узел»** — палитра с поиском, 74 типа узлов.
- Связи тянутся мышью от пина к пину; клик по связи удаляет её.
- Колесо или щипок — зум, перетаскивание фона — панорама, **«Вписать»** — показать весь граф.
- **«Разложить»** — автоматическая раскладка, **«Проверить»** — валидация графа.

| Клавиша | Действие |
|---|---|
| `Ctrl+A` | выделить все узлы |
| `Ctrl+D` | дублировать выделенные |
| `Del` или `X` | удалить выделенные |
| `F` | вписать граф в экран |
| `Esc` | закрыть редактор (граф применяется) |

Граф сохраняется внутри компонента и переживает сериализацию сцены — то есть работает
и в собранном APK.

## 7. Сборка APK

Из редактора: меню **«Ещё»** справа → **«Собрать APK»**. Имя приложения и пакет
подставляются из настроек проекта — остаётся нажать «Собрать APK» и скачать файл.

Из командной строки:

```bash
# простейший вариант — демо-сцена внутри
npm run apk -- --name "Моя игра" --package com.studio.game

# со своей сценой, экспортированной из редактора
node tools/cli.mjs apk --scene my.wflscene.json --out build/game.apk

# сведения о готовом файле
node tools/cli.mjs info game.apk
```

Полезные опции: `--portrait` (портретная ориентация), `--version 1.2`, `--version-code 5`,
`--min-sdk 21`, `--debug`, `--key key.pem --cert cert.pem` (своя подпись вместо
автоматически сгенерированной). Полный список — `node tools/cli.mjs help`.

Установка на телефон: `adb install -r game.apk` либо скиньте файл на устройство и
откройте его, разрешив установку из неизвестных источников. APK подписан схемами v1 и v2.

## 8. Прод-сборка сайта

```bash
npm run build     # результат в dist/
npm run preview   # локальный просмотр собранного
```

## 9. Тесты

```bash
npm test          # 10 наборов, в т.ч. 154 проверки блюпринтов и 51 проверка оболочки
```

Отдельно есть smoke-тесты интерфейса — они не входят в `npm test`, потому что требуют
необязательную зависимость `jsdom`:

```bash
npm install --no-save jsdom
node tools/test/manual/shell-ui-smoke.mjs    # главный экран и режим игры (60 проверок)
node tools/test/manual/editor-ui-smoke.mjs   # редактор сцены (72 проверки)
node tools/test/manual/app-flow-smoke.mjs    # сквозной сценарий (31 проверка)
node tools/test/manual/bp-ui-smoke.mjs       # редактор блюпринтов (27 проверок)
```

## Если что-то не запускается

**`Cannot find package 'esbuild'` / `'vite'`** — не выполнен `npm install`.

**`Port 3000 is already in use`** — порт занят прошлым запуском. Освободите его
(`kill $(lsof -t -i:3000)`) или укажите другой: `npx vite --host 0.0.0.0 --port 3100`.

**Пустой экран, в консоли ошибки WebGL** — нужен браузер с поддержкой WebGL 2
(актуальные Chrome, Firefox, Safari) и включённым аппаратным ускорением.

**Не собирается APK** — проверьте, что рантайм собран: `npm run build:runtime`.
Он создаёт `src/apk/runtime-bundle.js`, которого нет в git.

**Пропали проекты** — они лежат в `localStorage` конкретного браузера и домена.
Режим инкогнито, очистка данных сайта или другой браузер — и список будет пустым.
Чтобы не потерять работу, выгружайте важные проекты кнопкой «Экспорт в файл».
